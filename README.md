## 6 个类型，8 种结果

9 道题测 3 个维度，组合出 8 个位置——其中 6 个有鲜明人格，另外 2 个输出为混合型。

| 维度 | 两极 |
|---|---|
| **你怎么下决定** | 凭感觉 / 有算计 |
| **你要不要结构** | 整装（要一套完整的）/ 散装（自己拼） |
| **你的时间偏好** | 即时（先吃再说）/ 延后（可以等） |

| 类型 | 身份 | 套餐 |
|---|---|---|
| **老样子** | 用重复消除选择的人 | 巨无霸 + 中薯条 + 可乐 |
| **中薯换大薯** | 用"更多"对抗"不够"的人 | 双层吉士 + 大薯条 + 麦旋风 |
| **可乐换无糖** | 每个选择都要有理由的人 | 巨无霸 + 可乐 |
| **先来个甜的** | 把"现在"放在"应该"前面的人 | 麦旋风 + 香芋派 + 麦辣鸡翅 |
| **这个要啃** | 过程本身就是目的的人 | 麦辣鸡翅 + 麦乐鸡 + 雪碧 |
| **不要主食** | 拒绝被规定的人 | 麦乐鸡 + 中薯条 + 圆筒 |

**每个类型都有：** 一句身份、优势、阴影、最矛盾的地方、和谁像 / 和谁相反 / 和谁合不来（各带一句理由）。

## 计分规则（你可以自己核对）

不涉及随机数、不涉及加权，9 道题每题只值 1 分：

- **A 维度 · 你怎么下决定** = Q1 + Q2 + Q3，选第一个选项得 1 分。**≥2 记「算计」，否则「凭感觉」**
- **B 维度 · 你要不要结构** = Q4 + Q5 + Q6，同上。**≥2 记「整装」，否则「散装」**
- **C 维度 · 你的时间偏好** = Q7 + Q8 + Q9，同上。**≥2 记「即时」，否则「延后」**

三个维度的组合直接决定类型。页面上有一个「这次的分数」折叠区，会把你每一维的得分和阈值写出来，对着上面这三行就能自己验算。

**名字不参与计算。** 结果页有一个可选的「给小票签个名」输入框，它只改标题上的称呼，不会改变类型、套餐或分数。

## 三种人，三种吃法

| 类型 | 身份 | 套餐 | 合计 |
|---|---|---|---|
| **老样子** | 用重复消除选择的人 | 巨无霸 + 中薯条 + 可乐 | ¥50.0 / 949 kcal |
| **中薯换大薯** | 用"更多"对抗"不够"的人 | 双层吉士 + 大薯条 + 麦旋风 | ≈¥50.5 / 1,074 kcal |
| **先来个甜的** | 把"现在"放在"应该"前面的人 | 麦旋风 + 香芋派 + 麦辣鸡翅 | ≈¥35.5 / **722 kcal** |

**注意最后一行**：热量最低的那一单，不是"最克制"的「可乐换无糖」，而是「先来个甜的」——它只有三样，其中两样是甜品。这就是为什么不能"喜欢什么就归成什么人格"：**甜食党的热量未必高，控糖党的矛盾可能最大。**

每份套餐都是从**麦当劳真实菜单**里取的：餐品名来自门店在售商品，价格是门店实价，热量与营养成分取自官方 `list-nutrition-foods`（160 条真实数据）。不是文案拼出来的。

## 每个类型的套餐是固定的

类型决定套餐，套餐决定成分表。所以你测出来的那张小票，换成别人测同一个类型，东西是一样的——**能比较的才是人格，随机的不算。**

## 成分表：这张表只有这个项目做得出来

```
成分表（每份你的套餐）
─────────────────────
碳水        41%    ← 98 g × 4 kcal = 392，占三大营养素热量 44.7%
脂肪        38%    ← 40 g × 9 kcal = 360，占 41.1%
蛋白质      13%    ← 31 g × 4 kcal = 124，占 14.2%
纠结         5%    ← 这一项不算营养，算你
贪心         3%
─────────────────────
合计       100%
```

**前三项是真的**：把你这份套餐里每样餐品的碳水 ×4、脂肪 ×9、蛋白质 ×4 折算成热量，再求各自占比。荒诞成分（2%–8%）从真实占比里按比例扣掉，保证整张表恒等于 100%。

张三这份的完整推导：98×4 + 40×9 + 31×4 = **876 kcal**，而四件套官方热量是 **886 kcal**，差 1.1%——这个 1.1% 我们没抹平，就写在那里，因为它说明这些数字是算出来的，不是凑出来的。

**为什么别人做不出来**：答题类人格测试没有营养数据。我们有，因为真的接了麦当劳 MCP。全文 400 种组合逐一验算，合计恒为 100%，无负数。

### 小票上那个井号是什么

结果页小票上有一串 `#xxxxxxx`。它是**名字的 FNV-1a 哈希**：没签名时隐藏，签了名就是这个名字的固定指纹，同一个名字永远同一串。

**它只是小票上的编号装饰，不参与类型计算。** 类型和套餐完全由你的 9 个选择决定。

## 用你自己的真实订单（可选，进阶）

看完自己的人格，你可能想知道：**我在麦当劳到底花了多少钱？**

这个数字不能靠手填——手填就是编。必须从你的真实订单里读。

由于麦当劳 MCP **不允许浏览器跨域调用**（OPTIONS 预检直接返回 403），网页端无法直连。所以做法是：

```bash
# 1. 拿到 Token（open.mcd.cn/mcp 手机号登录后激活）
export MCD_MCP_TOKEN=你的token      # Windows: set MCD_MCP_TOKEN=你的token

# 2. 导出你的真实订单（只读，不会下单）
python export_orders.py

# 3. 回到网页，点「导入我的订单」，选择生成的 my-orders.json
```

网页会算出：

- 你在麦当劳一共花了多少、下了几单、横跨几个月、去过几家店
- 这笔钱相当于**多少份你自己的套餐**、多少平米鹤岗房子、几台 iPhone、几张电影票
- 你点得最多的那个餐品是什么

**订单数据只在你本地计算，不会上传到任何地方。**

## 设计上的几个取舍（以及为什么）

| 取舍 | 选择 | 原因 |
|---|---|---|
| 结果怎么产生 | 9 道题 → 3 个维度 → 类型 | 用户要真的做选择，结果才值得讨论。名字只是签名 |
| 类型数量 | 6 个 + 2 个混合型 | 3 维理论上有 8 个位置，但只有 6 个有鲜明行为差异；另外 2 个硬造就是凑数 |
| 题目形式 | 情境二选一 | 不问"你是不是独立的人"，问"麦旋风来了但正餐没上，你先吃哪个" |
| 是否加权 | 不加权 | 每题 1 分、阈值 2 分，用户能自己核对，不需要信我 |
| 是否用大模型 | 不用 | 大模型会让同一组答案给出不同结果，那这个测试就没法比较了 |
| 是否联网 | 不联网 | 打开即玩，没有转圈和报错，传播摩擦最小 |
| 名字的作用 | 只做签名 | 名字不参与计算，避免"名字决定命运"这种算命观感 |
