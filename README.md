# 你的名字是一份麦当劳套餐

输入名字，用 FNV-1a 哈希从真实菜单里确定性地抽出一份「主食 + 小食 + 饮料 + 甜品」四件套，生成一张可截图的套餐凭证。同名永远同套餐。

参加 **麦当劳 1024 程序员创意开发大赛** 的参赛作品。纯前端单文件，零依赖、零构建、零网络请求。

---

## 怎么打开

双击 `index.html` 即可，不需要装任何东西、不需要起服务器、不需要联网、不需要 Token。

手机上也能用：把文件传到手机用浏览器打开，或部署到任意静态托管（GitHub Pages / Vercel / OSS 均可）。

---

## 玩法

1. 输入名字（中文、英文、中英混排都行），回车或点「生成我的套餐」
2. 得到一张套餐凭证：套餐名、四件商品与单价、合计金额与热量、一句评语、常见度与哈希指纹
3. 点「复制文案」发到微信，问一句「你的名字是什么套餐？」
4. 算出套餐后，下方才出现第二屏：填一年在麦当劳的花销，换算成套餐份数、鹤岗房子平米数、iPhone 台数、电影票张数

## 哈希规则（可以自己验证）

不涉及任何随机数、时间戳或服务端请求。浏览器控制台里可以直接调 `window.MealHash.buildMeal('你的名字')` 复查。

### 第一步：归一化

```js
const key = name.trim().toLowerCase();
```

### 第二步：编码成 UTF-8 字节

FNV-1a 标准定义迭代的是**字节**，不是 UTF-16 码元。所以中文必须先按 UTF-8 编码，否则结果与任何标准实现都对不上（一个汉字 3 字节，一个 emoji 4 字节）。

```js
const bytes = new TextEncoder().encode(key);
```

### 第三步：FNV-1a 32 位哈希

```js
let h = 2166136261;                 // 0x811c9dc5，FNV offset basis
for (const b of bytes) {
  h ^= b;
  h = Math.imul(h, 16777619) >>> 0; // 精确 32 位乘法，等价于 (h * 16777619) mod 2^32
}
```

`Math.imul` 是 ECMAScript 标准，做 32 位有符号乘法且不丢精度，可以直接拿去和任何语言的实现对照。

标准测试向量（可与任何 FNV-1a 实现交叉验证）：

| 输入 | 期望值 | 十六进制 |
| --- | --- | --- |
| `""` | 2166136261 | `811c9dc5` |
| `"a"` | 3826002220 | `e40c292c` |
| `"foobar"` | 3214735720 | `bf9cf968` |
| `"hello"` | 1335831723 | `4f9f2cab` |
| `"张三"` | 956401659 | `390187fb` |
| `"李雷"` | 887838239 | `34eb561f` |
| `"李四"` | 2249836199 | `8619c6a7` |

### 第四步：按字节位取四件商品

```js
主食 = 主食池[(h >>> 0)  % 5];   // 第 0 字节
小食 = 小食池[(h >>> 8)  % 5];   // 第 1 字节
饮料 = 饮料池[(h >>> 16) % 4];   // 第 2 字节
甜品 = 甜品池[(h >>> 24) % 4];   // 第 3 字节
```

池子规模 5 × 5 × 4 × 4 = **400 种组合**。

### 第五步：常见度与指纹

```js
常见度 = ((h >>> 0) % 1000) / 10;        // 输出形如 65.9%
指纹   = (h >>> 0).toString(16).padStart(8, '0');  // 形如 390187fb
```

常见度是把哈希值映射到 0.0%–99.9% 的趣味指标，**数值越大表示这一档越常见**（65.9% 就是「很常见」），全程不取反、不加随机，**不是**统计意义上的概率。

## 实现说明

| 项 | 说明 |
| --- | --- |
| 文件 | 单个 `index.html`，约 45 KB，含全部样式与逻辑 |
| 依赖 | 无。没有 CDN、没有外部字体、没有图标库、没有 `html2canvas` |
| 请求 | 无。菜单数据硬编码在文件里，断网可用 |
| 确定性 | 无 `Math.random`、无 `Date`，纯哈希函数，刷新结果不变 |
| 哈希标准 | 严格按 FNV-1a 定义：先 UTF-8 编码再逐字节迭代，`Math.imul` 做精确 32 位乘法。中文名可用任何标准实现复算 |
| 金额格式 | 商品单价与合计统一 `¥x.x`，例如 `¥9.0`、`¥46.5` |
| 命名优先级 | 辣味最高：主食或小食带辣就走辣味模板，再按肉种 → 咖啡 → 甜品细分，共 24 桶 102 个名字 |
| 页面节奏 | 首屏只有名字输入；算出套餐后结果卡与消费换算卡才依次出现 |
| 分享 | 「复制文案」优先用 Clipboard API，`file://` 下自动退回 `execCommand`，再失败弹手动复制面板 |
| 兼容 | 现代浏览器 + 移动端；`prefers-reduced-motion` 下关闭动画；无 `TextEncoder` 的极老环境走内置 UTF-8 编码器，输出一致 |
| 自测 | `window.MealHash.buildMeal(name)` / `.fnv1a(name)` / `.encodeUtf8(name)` 可在控制台复查任意名字 |

### 已知取舍

- **热量分档阈值**：实际情况可生成的套餐热量区间是 **628 – 1305 kcal**，原设想的「> 1400 kcal」档永远不会触发，因此阈值定为 `≥1200 / ≥1000 / ≥850 / <850` 四档。
- **套餐名复用**：24 个特征桶（辣味 6 + 常规 18）× 每桶 4–5 个候选 = **102 个套餐名，全局无重复**，覆盖 400 种组合。同桶的组合仍可能共用一个名字，但商品清单始终逐项列出，不会误导。
- **常见度不取反**：直接显示 `(h % 1000) / 10`，数值越大越常见；页面不再配任何可能与之矛盾的副标题。
