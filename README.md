## 成分表：这张表只有这个项目做得出来

```
成分表（每份你的套餐）
─────────────────────
碳水        41%    ← 98 g × 4 kcal = 392，占三大营养素热量 44.7%
脂肪        38%    ← 40 g × 9 kcal = 360，占 41.1%
蛋白质      13%    ← 31 g × 4 kcal = 124，占 14.2%
纠结         5%    ← 这一项不算营养，算你
贪心         3%
─────────────────────
合计       100%
```

**前三项是真的**：把你这份套餐里每样餐品的碳水 ×4、脂肪 ×9、蛋白质 ×4 折算成热量，再求各自占比。荒诞成分（2%–8%）从真实占比里按比例扣掉，保证整张表恒等于 100%。

张三这份的完整推导：98×4 + 40×9 + 31×4 = **876 kcal**，而四件套官方热量是 **886 kcal**，差 1.1%——这个 1.1% 我们没抹平，就写在那里，因为它说明这些数字是算出来的，不是凑出来的。

**为什么别人做不出来**：答题类人格测试没有营养数据。我们有，因为真的接了麦当劳 MCP。全文 400 种组合逐一验算，合计恒为 100%，无负数。

## 它是怎么算的（你可以自己验证）

不涉及任何随机数、时间戳、服务端请求。全程只有四步：

### 第一步：归一化

```python
key = name.strip().lower()
```

### 第二步：编码成 UTF-8 字节

FNV-1a 标准迭代的是**字节**，不是 UTF-16 码元。所以中文必须先按 UTF-8 编码——一个汉字 3 字节，一个 emoji 4 字节。

```python
data = key.encode('utf-8')
```

### 第三步：FNV-1a 32 位哈希

```python
h = 2166136261                      # 0x811c9dc5, FNV offset basis
for b in data:
    h ^= b
    h = (h * 16777619) & 0xFFFFFFFF  # mod 2^32
```

### 第四步：按字节位取四件商品

```python
主食 = 主食池[(h      ) % 5]
小食 = 小食池[(h >> 8 ) % 5]
饮料 = 饮料池[(h >> 16) % 4]
甜品 = 甜品池[(h >> 24) % 4]
```

5 × 5 × 4 × 4 = **400 种组合**。

## 用你自己的真实订单（可选，进阶）

看完自己的人格，你可能想知道：**我在麦当劳到底花了多少钱？**

这个数字不能靠手填——手填就是编。必须从你的真实订单里读。

由于麦当劳 MCP **不允许浏览器跨域调用**（OPTIONS 预检直接返回 403），网页端无法直连。所以做法是：

```bash
# 1. 拿到 Token（open.mcd.cn/mcp 手机号登录后激活）
export MCD_MCP_TOKEN=你的token      # Windows: set MCD_MCP_TOKEN=你的token

# 2. 导出你的真实订单（只读，不会下单）
python export_orders.py

# 3. 回到网页，点「导入我的订单」，选择生成的 my-orders.json
```

网页会算出：

- 你在麦当劳一共花了多少、下了几单、横跨几个月、去过几家店
- 这笔钱相当于**多少份你自己的套餐**、多少平米鹤岗房子、几台 iPhone、几张电影票
- 你点得最多的那个餐品是什么

**订单数据只在你本地计算，不会上传到任何地方。**

## 设计上的几个取舍（以及为什么）

| 取舍 | 选择 | 原因 |
|---|---|---|
| 抽签方式 | 哈希，不是随机数 | 随机数无法验证；哈希可以被任何人复算 |
| 菜单数据 | 内嵌快照 | 门店实时菜单以套餐组合为主、单品命名不统一，直接用于四分类会不稳定 |
| 是否联网 | 不联网 | 打开即玩，没有转圈和报错，传播摩擦最小 |
| 是否接大模型 | 不接 | 大模型会让同一个名字在不同时间给出不同结果，直接摧毁"同名同人格"这个承诺 |
| 文案里的"命理" | 一个字都不写 | 这是密码学，不是算命；也说清楚免得被误解 |
